Baseline: `9b4120f1c2f1943b491d7378bcea18efd15a2350`.
Ветка: `local/learning-value-20261101`. Изменены только `value_model.py`,
`vendor/value_model.h`, `test_value_model.py` и этот документ. Core, default,
старые партии, ADB и рабочий бот не менялись. Новое обучение на партиях не
выполнялось; тест обучения использует небольшой искусственный набор.

## Назначение и граница

Модель оценивает позицию после собственного хода, до появления новой плитки.
Метка — исход целой партии: три несливающиеся плитки уровня 11 = 1, проигрыш = 0.
Это supervised MC-модель, не TD/RL-обучение и не доказанно калиброванная
вероятность. Сохранённые веса классической 2048 не принимаются как этот формат.

Необученная Python-модель имеет нулевые веса и даёт 0.5 в незавершённых
позициях. Goal всегда даёт 1; поле без легального хода — 0. Уровни >=11 не
сливаются, но только точный уровень11 считается готовой CAP. Пустое поле
рассматривается как терминально неуспешное диагностическое состояние.

Четыре паттерна по четыре клетки: `(0,1,2,3)`, `(0,1,4,5)`, `(0,1,2,5)`,
`(0,1,5,6)`. Для каждого усредняются восемь D4-представлений. Веса общие
между симметриями. Всего32 lookup на оценку; C++ использует предвычисленные
индексы клеток, не строит преобразованные поля в каждом листе. Три независимые
стадии — ноль, одна и две/более готовых11. Alphabet16 сохраняет совместимость
с упаковкой тетрадами; семантика обычных опытов по-прежнему CAP11/GOAL3.

Число float32-весов: `3*4*65536=786432`, плюс три bias. Payload занимает
3145740 байт (3 MiB +12 байт). Логит — `bias[stage]+sum(32 weights)/8`,
выход — численно устойчивая sigmoid. Goal/loss обходят оценщик признаков.

## Python API

```python
from value_model import ValueModel, features

model = ValueModel()
stage, indices = features(board)  # indices: ndarray uint16, shape (4,8)
metrics = model.fit(
    train_records,
    validation_records=validation_records,
    epochs=8, learning_rate=0.5, l2=1e-4,
    patience=3, min_delta=0.001, batch_size=256, seed=0,
)
model.metadata.update(source_sha256=source_hashes, dataset_sha256=data_hashes)
manifest = model.save("candidate.bin")
restored = ValueModel.load("candidate.bin")
value = restored.predict(board)
```

Запись: `board` — 16 целых уровней0..15, `seed` — целый идентификатор партии,
`label` — бинарный исход, `episode_weight` необязателен. Все записи одного
seed должны иметь один MC-label. Противоречие terminal board/label отвергается.
Train/validation не могут делить seed, включая терминальные записи.

`fit` сам нормирует веса внутри seed до суммы1. Переданные координатором
`1/n_samples_per_seed` не взвешиваются второй раз: они также приводятся к
единичной сумме. `episode_weight` — относительный вес записи внутри партии,
а не способ изменить приоритет целой партии. Переполнение/неконечные веса и
неподдерживаемый динамический диапазон отвергаются.

Каждый fit начинает с нулевых табличных весов и bias по train-stage prior;
его не следует использовать как незаметное продолжение прошлого обучения.
Приоры ограничены интервалом `[1e-4,1-1e-4]`. Затем применяется детерминированный
при заданном seed minibatch SGD с L2 и ограничением параметров `[-32,32]`.
Терминальные состояния не обновляют параметры. Веса записей дают одинаковую
суммарную массу каждой партии. Early stopping сохраняет epoch с лучшим Brier;
выбор epoch на validation является настройкой, а не финальным контролем.

Возврат `fit`, также доступный как `model.training`, содержит:

- `train_brier`, `validation_brier`, `stage_prior_validation_brier`;
- `validation_gate_passed`: улучшение относительно train-stage prior строго
  больше `min_delta` на validation; без validation всегда False;
- `best_epoch`, `history`, train/validation списки seed и числа записей;
- SHA256 упорядоченных входных записей и конфигурации обучения;
- способ взвешивания, приоры и `calibrated_probability=False`.

Проверка качества нужна на ещё не использованных партиях. Хороший Brier
модели не доказывает, что выбор хода с её помощью повышает процент побед.
Выборка validation с двумя исходами желательна; модуль не подменяет её
случайным разбиением соседних состояний.

`model.metadata` предназначен для дополнительного происхождения. `save`
также принимает keyword `metadata={...}`. Reserved-поля формата, архитектуры,
payload SHA и training нельзя подменять через extra. Их полноту проверяет
Python load. Сохранение атомарное через временный файл рядом с целью.

## C++ API и интеграция

```cpp
#include "value_model.h"
bonk_value::Model value;
std::string error;
bool ok = value.load(path, &error);
bool ready = value.loaded();
float score = value.evaluate(packed_board);
const std::string &metadata = value.metadata_json();
value.clear();
```

Это приватный header без внешних зависимостей и без правок ABI движка.
Координатор добавляет собственные optional exports. Загрузка и clear должны
происходить вне поиска; несколько потоков могут одновременно вызывать
`evaluate const` на уже загруженном неизменном объекте. Никаких mutex в каждом
листе не требуется. Незагруженная native-модель возвращает NaN, чтобы отсутствие
файла не превратилось в тихую игру с нейтральной оценкой. Ошибка load не меняет
ранее загруженные параметры или metadata.

В режиме learned value обе ранние проверки goal в движке должны возвращать1,
а не старые1e9; loss0 и `best=0` тогда имеют согласованную шкалу. В режиме
обычной эвристики её прежняя шкала сохраняется. После загрузки/переключения
модели кэши поиска не должны переиспользовать значения от другой модели.

## Бинарный формат версии1

Все целые и IEEE754 float32 — little-endian. Фиксированный header48 байт:

| Смещение | Поле | Значение |
|---:|---|---:|
| 0 | magic[8] | `BONKVAL1` |
| 8 | u32 version | 1 |
| 12 | u32 header size | 48 |
| 16 | u32 metadata byte length | 1..1048576 |
| 20 | u32 stages | 3 |
| 24 | u32 patterns | 4 |
| 28 | u32 table size | 65536 |
| 32 | u32 CAP | 11 |
| 36 | u32 GOAL_COUNT | 3 |
| 40 | u32 target type | 1: MC-afterstate goal outcome |
| 44 | u32 CRC32 | CRC(metadata bytes + payload bytes) |

Затем canonical UTF8 JSON (`sort_keys`, без пробелов и NaN/Inf), затем три
bias и786432 веса в порядке stage,pattern,index. Индекс паттерна — четыре
rank-тетрады, первая выбранная клетка находится в младших четырёх битах.
Версия1 фиксирует паттерны, D4-сопоставления, нормировку, sigmoid и правила
терминалов. Header нельзя использовать для другого набора паттернов или цели.

Python проверяет JSON, точную архитектуру, SHA256 payload и finite-параметры.
C++ проверяет фиксированные архитектурные/rules/target поля header, точный
размер, CRC32, формат float32 и отсутствие NaN/Inf. JSON остаётся opaque
аудиторскими metadata: C++ не интерпретирует историю обучения и не подтверждает
её правдивость. Перед native-загрузкой внешний пользователь должен применять
строгий Python load, как согласовано с координатором. CRC32 защищает от случайного
повреждения, не от умышленно подделанного файла. Семантика inference задаётся
фиксированной версией header, а не произвольным JSON.

## Проверки

Команда: `python3 -m unittest -v test_value_model.py`.

Восемь тестов проверяют известное nibble-кодирование, D4-замкнутость признаков,
стадии/terminal goal/loss, обучение на контрастных искусственных состояниях,
детерминизм, отсутствие утечки seed, эпизодное взвешивание, byte-identical
roundtrip, сохранение extra-происхождения, согласование Python/C++ на49 полях
и восьми симметриях каждого, отказ от повреждённых форматов/NaN/Inf и отсутствие
частичной native-загрузки. C++ адаптер компилируется только во временной папке,
production engine и build.sh не изменяет. Синтетическое обучение не доказывает
силу игрового кандидата; данных старого контроля в нём нет.
