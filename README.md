# 2048 — Автоигра: Звёздное провидение

Откройте поле на подключённом телефоне. Дважды нажмите `Запустить.command`. Для остановки — `Остановить.command` или Ctrl+C. Не играйте вручную одновременно с ботом. scrcpy можно оставить открытым.

Цель: три плитки ровно 13 одновременно (три 8192 в обычной 2048). При достижении бот сохраняет goal.png и останавливается. Он по возможности сохраняет 13 от слияния. Энергия расходуется по правилам игры. Покупки, инструменты и перезапуск проигранной партии не автоматизированы.


## Установка и запуск (macOS)

Локальный Python/ADB-бот для мобильного режима «Звёздное провидение» с механикой 2048. Калибровка привязана к интерфейсу игры; для обычной 2048 потребуется адаптация распознавания.

Нужны Python 3, ADB (`android-platform-tools`), Tesseract с английским языком и Xcode Command Line Tools с `clang++`.

```sh
git clone https://github.com/Shalioner/2048.git
cd 2048
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
sh vendor/build.sh
adb devices
zsh ./Запустить.command
```

Подключите Android по USB, разрешите отладку и откройте поле игры. При нескольких устройствах: `zsh ./Запустить.command --serial ВАШ_SERIAL`.

Остановка из другого терминала в папке проекта: `zsh ./Остановить.command`, либо Ctrl+C в окне бота. Команды используют папку своего расположения. После установки через venv запускайте из терминала с активированной средой.

Проверка без телефона и жестов: `python3 -m unittest -v test_bot.py`.

Исходники взяты из архива `2048-исходники.zip`. Движок собирается из C++-исходников; готовый бинарник в Git не включён. Ниже сохранён журнал разработки: упоминаемые в нём локальные логи и сводки в исходный архив не входили. Достижение цели не подтверждено. Публикация проверена локально: сборка C++-движка, 22 теста и синтаксис команд запуска прошли. Управление телефоном при публикации не проверялось.

## Скорость

Для текущего SM-G975F (1440×3040) передаются четыре полосы со значками из одного кадра через `screencap | dd`: около 0,6 с вместо 1,0–1,3 с для всей области поля, 1,7–2,1 с для полного raw-кадра и 5,4 с для PNG. Свайп 100 мс; пауза по умолчанию 400 мс. Полное время цикла выводится как cycle_s. Первый ход с неизвестной цифрой и повторное чтение после анимации могут быть медленнее.

Другие размеры используют полный raw-кадр. Масштабирование поддерживается только при сохранении пропорций интерфейса. `--delay` задаёт паузу; `--steps` — предел ходов; `--serial` — телефон. `--dry-run` читает поле без ходов.

## Выбор ходов

C++ expectimax из https://github.com/nneonneo/2048-ai (MIT), исходники и лицензия в vendor. Таблицы слияний и эвристик, кеширование состояний, отсечение маловероятных ветвей; глубина поиска до 7 ходов игрока (маловероятные ветви отсекаются). На телефоне подтверждено появление новой плитки уровня 3. Начальные веса 85/10/5 для уровней 1/2/3 являются рабочим предположением. Каждый проверенный ход обновляет веса по наблюдённому появлению; модель сохраняется в spawn-model.json. Точное распределение игры пока неизвестно.

Локальная адаптация engine_adapted.cpp добавляет цель три 13 и сохранение 13 при наличии альтернативы во внутренних узлах поиска. bot.py отбирает допустимые ходы для той же цели. Стандартные 2/4/8 соответствуют здесь уровням 1/2/3. Оригинальные 2048.cpp, 2048.h, platdefs.h сохранены. Пересборка на macOS: `sh vendor/build.sh`. Движок запускается локально, данные телефона никуда не отправляются.

В сравнении на трёх seed по 500 ходов при стандартном появлении 90/10 прежний алгоритм достиг уровней 9,10,9, новый — 10,10,10. Это короткая симуляция, не доказательство победы в реальной игре. Результаты в benchmark.json. Высокие уровни 10–13 на реальном экране пока не проверены.

## Проверки и остановки

`python3 -m unittest discover -s merge-game-bot -p test_bot.py`: 16 тестов. Включают 2000 сравнений слияний Python/C++, цели, сохранение 13, PNG/raw/crop, калибровку и чтение уровня 7, семёрку с разрывом начертания и декодирование четырёх полос. Неизменяемый проблемный кадр хранится в fixtures.

Перед каждым жестом проверяется фокус игры. После хода проверяются слияние и появление одной плитки 1, 2 или 3. Кадр с незавершённой анимацией перечитывается; при устойчивом расхождении сохраняется recognition-error.png и бот останавливается. Если поле не меняется, бот останавливается (в том числе при исчерпании энергии). Второй экземпляр блокируется.

Зависимости этой машины: Python, Pillow, numpy, OpenCV, adb, tesseract и локальная vendor/engine.dylib. Журнал фоновой игры — play.log, PID — running.json.

Живая приёмка 2026-10-29: 20 ходов завершены без остановки по ошибке. Обычно 1,75–1,94 с на цикл; первый цикл 2,006 с, один цикл с повторным чтением анимации 3,749 с. Цель ещё не достигнута. Сводка verification.json.

Захват полос содержит только значки плиток: latest.png в диагностическом режиме показывает полосы. Для goal.png и recognition-error.png запрашивается полный кадр телефона.

Проверка захвата четырёх полос: {'moves': 25, 'cycles': 24, 'median_s': 1.3705, 'min_s': 1.3, 'max_s': 1.569, 'under_1_5': 23, 'unit_tests': 12}
Серия 25 ходов завершена, достигнут и распознан уровень 8. Полные замеры в speed-trial.log, сводка speed-verification.json. Глубина C++-поиска и проверки переходов сохранены.

Текущая цель изменена на три 13 одновременно. Одна 13, две 13, три 11 и плитка 14 сами по себе не останавливают игру. Проверка Python и C++ использует одинаковое условие. Достижение новой цели пока не подтверждено. Старые benchmark.json и speed-verification.json относятся к прежней цели.

При смене цели: 16 тестов прошли, пять реальных ходов выполнены; бот перезапущен с целью три 13. Текущий максимальный наблюдавшийся уровень — 8.

## Исправление модели игры 2026-10-29

Проверено через ADB: после последнего свайпа вверх из журнала поле совпадает с моделью слияния, но в клетке (4,4) появилась новая 3. Старый код разрешал только 1/2 и останавливался. Сохранённый исходный кадр fixtures/spawn-three.png воспроизводит ошибку (тест падал до исправления).

В поиске C++ раньше ветвь появления 3 отсутствовала. Она добавлена с обновляемыми весами; статистика выбора теперь пишется в журнал как spawn_level, cell, spawn_weights. При прочих расхождениях бот сохраняет остановку и выводит ожидаемое и фактическое поля. Тест на новую 3 проходит; отдельный тест подтверждает, что её вероятность влияет на оценку C++.

Всего 16 тестов прошли. Повышенная глубина на плотном поле может увеличивать время хода. Эффективность достижения трёх 13 этим исправлением не доказана; старые короткие benchmark не моделировали появление 3.

Живая проверка исправления: 15 ходов без остановки по ошибке; счёт 2544 → 2784, поле после серии имеет 3 свободные клетки. Медиана полного цикла 1,82 с, максимум 3,013 с на плотном поле. Максимальная плитка остаётся 8. Сводка spawn-fix-verification.json, журнал spawn-fix-live.log, полный снимок after-spawn-fix.png.

По запросу пользователя глубина действующего C++-решателя установлена в 7 на всех полях. Это верхний предел с вероятностным отсечением, а не полный перебор всех ветвей на 7 ходов. Время хода может увеличиться.

## Расширяемая модель появления плиток

Через ADB подтверждена новая 4: fixtures/spawn-four.png. Старое ограничение 1..3 вызывало остановку. Движок теперь принимает вектор вероятностей уровней 1..15; вероятности ненаблюдавшихся уровней равны нулю. Существующий файл spawn-model.json дополняется нулевыми весами; для независимо подтверждённой 4 добавляется вес 1.

Переход по-прежнему обязан совпасть со слиянием во всех клетках кроме одной ранее пустой клетки. Допустим новый уровень не выше max(4, максимальный существующий уровень), в пределах 15. Впервые встретившийся уровень с нулевым весом подтверждается вторым стабильным кадром без нового жеста; затем записывается в статистику и учитывается C++-поиском. Несовпадение остальных клеток останавливает бота. Это проверка состояния, а не гарантия оптимальности хода.

Проверка: регрессия появления 4 падала до исправления; после исправления 17 тестов проходят. Глубина остаётся 7, на некоторых полях ход занимает более двух секунд. Бот возобновлён; фоновый журнал play.log.

## Подтверждение жестов и анимаций

При наблюдении через ADB обнаружены временные ошибки цифр во время анимации (3 читалась как 5). Раньше неизменившееся поле допускало повторную отправку жеста, даже если первый ход ещё не завершился. Теперь отправляется DOWN → один MOVE → UP; следующий жест разрешён только после двух одинаковых кадров, соответствующих рассчитанному слиянию и одной новой плитке. Если поле ещё старое, бот только перечитывает экран, не повторяя жест. Максимум 15 наблюдений, затем остановка с полным кадром.

На телефоне свайп 1 мс не дал немедленного подтверждения, а чтение через 0,5 с после одиночного MOVE показало временную ошибку цифры; более поздний полный кадр подтвердил ожидаемую 3. Поэтому сокращение ожидания без подтверждения результата небезопасно для этой игры.

18 тестов проходят, включая запрет подтверждать старый кадр, непроверенный первый кадр и временное несоответствие. Глубина остаётся 7. Из-за повторного кадра полный ход обычно медленнее прежних замеров; актуальные измерения в stable-gesture-trial.log.

Живая проверка однократного MOVE и подтверждения кадра: 30 ходов без остановки по ошибке, медиана цикла 2,036 с, максимум 2,822 с. Сводка stable-gesture-verification.json, журнал stable-gesture-trial.log. После проверки возобновлён длительный запуск с той же глубиной 7.

После исправления подтверждения ходов бот собрал уровень 10, счёт достиг 8828. Обнаружен и исправлен узкий crop цифры: окно расширено с 49 до 69 пикселей, чтобы не терять первую цифру. Регрессия fixtures/level-ten.png проверяет всё поле с плиткой 10. Все 19 тестов проходят; после расширения возобновлён запуск с глубиной 7. Плитки 11–13 на реальном экране пока не наблюдались.

Дополнительно двузначные уровни распознаются посимвольно: первая 1 и 0 откалиброваны из настоящей плитки 10, вторые цифры — по шаблонам игры. Синтетические 11/12/13 проходят проверку; реальные 11–13 пока не наблюдались. Всего 20 тестов прошли. После расширения crop наблюдение за живым запуском в течение 60 секунд показало 30 ходов без ошибок, максимум 10.

При временном сбое чтения полос сохраняются точные данные failed-observation.bin и observation_error в журнале. Бот переключается на полные кадры до подтверждения хода. Последняя ошибка распознавания теперь входит в итог остановки. Проверка резервного чтения добавлена; 21 тест проходит. Причину прошлой временной ошибки точно установить нельзя: до этого текст исключения не сохранялся, а свежий полный кадр уже читался нормально.

Добавлена независимая проверка предметов 3/4/5 по иконкам на полном кадре: нормированная корреляция не ниже 0,94 и отрыв от второго кандидата не ниже 0,12. При отсутствии иконки в быстрых полосах используется распознавание цифры. Несоответствие перехода теперь также переключает наблюдение на полные кадры. Регрессия с принудительно ошибочной цифрой 4 вместо 3 падала до исправления, теперь проходит. Всего 22 теста проходят. Прежняя отложенная доработка завершена. На реальном экране подтверждена и корректно прочитана плитка 11, счёт 19340.
