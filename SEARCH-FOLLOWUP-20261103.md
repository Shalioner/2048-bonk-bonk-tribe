# Дополнительный отбор оптимизаций, 3 ноября 2026

**Нового подтверждённого ускорения нет. Все 11 вариантов отклонены; рабочий
движок остаётся на коде `6fedfa2`, исходная точка сравнения — `08992d5`.**
Предыдущее принятое улучшение и его отдельные измерения описаны в
[SEARCH-LEAF-OPTIMIZATION.md](SEARCH-LEAF-OPTIMIZATION.md).

Задача: ещё ускорить принятие решений без потери точности поиска, проверить
результаты компактным агентом. Координатор подготовил варианты, агент
GPT-6 Luna low выполнил проверки и замеры, координатор проверил сырые JSON,
комплектность данных и SHA-256 библиотек. Независимый агент проверил логику
пропуска глубин и нового предиката цели; корректность сама по себе не стала
основанием для переноса в main.

Пропуск глубин измерен отдельно: четыре заранее заданных поля, один вызов
progressive на движок с обычным бюджетом 10 секунд. Медиана задержки
**3,281 → 3,424 секунды**. Проходов иногда стало меньше, но ускорение
пользовательского решения не подтвердилось. p95 на четырёх значениях —
фактически максимум; статистической оценки хвоста здесь нет.

Для остальных вариантов: 21 поле `corpus(seed=2048)`, глубина 8, порог
`1e-4`, два повтора, циклическая смена порядка движков. Измерение включает
последовательный расчёт четырёх направлений. Медиана и p95 рассчитаны по
42 вызовам на движок, а не по 42 независимым игровым позициям. Набор общий
для всех вариантов и использован для отбора, не для независимого финального
подтверждения. Критерий допуска к следующему этапу: минимум 5% улучшения
медианы и p95 без ухудшения максимума. Ни один вариант его не выполнил.

## Точность и границы проверки

- В каждом из десяти фиксированных вариантов совпали все четыре float-оценки
  с baseline на всех 21 полях и обоих повторах: 168 сравнений на вариант.
  Это проверка точного совпадения, а не допустимого отклонения.
- Для кандидата пропуска глубин прошли **195 unittest**, включая 7 новых,
  и `verify_search.py`: **800 оценок и 200 решений allowed-mask**.
  Его дополнительные тесты отдельно запускались на baseline и выявляли
  ожидаемое отсутствие нового поведения.
- Остальные десять вариантов прошли только отбор с совпадением оценок;
  полный suite для них не запускался. Они не перенесены в рабочий движок.
- Повторный тест побед и независимый контрольный корпус не запускались:
  кандидаты не прошли предварительный скоростной критерий. Новых данных
  об изменении вероятности побед нет. Точность распознавания экрана этим
  экспериментом не проверялась.
- Попытка системного профилирования через `sample` была отклонена macOS.
  Права не повышались; время под профилированием не использовалось в таблице.
- Телефон, ADB и реальные игровые жесты не использовались.

## Воспроизводимость и состояние

[Артефакты](verification/search-followup-20261103/) содержат сырые результаты,
логи, отдельные коды завершения, скрипты, протоколы, патчи относительно
`08992d5`, сводку и SHA-256 исходников/библиотек. Повторные измерения должны
использовать новый каталог результатов: скрипты отбора перезаписывают JSON.

Исходная локальная лаборатория:
`../output/2048-progressive-saturation-20261103/` относительно репозитория.
В ней сохранены checkout baseline и всех кандидатов, собранные библиотеки
и результаты. Например, из неё можно повторить `python3 goal_screen.py`.
Скрипты в папке артефактов предполагают ту же структуру лаборатории;
их нельзя запускать непосредственно внутри папки доказательств.

Для восстановления фиксированного кандидата в отдельном worktree: взять
`08992d5`, применить соответствующий `.patch` через `git apply`, собрать
`sh vendor/build.sh`. Патчи меняют только исходник движка. Патч saturation
также содержит тесты и обновление генератора экспериментальных вариантов;
его код сохранён отдельным коммитом `a8d0441`.

SHA-256 установленной рабочей библиотеки после опытов совпал с baseline.
Рабочие файлы движка, бота, модели появлений и настройки не менялись.
Этот проход добавляет только документацию и доказательства отрицательного
результата. Отказ от кандидатов сохраняет предыдущее принятое ускорение.
GitHub не обновлялся.
