## Зафиксировано до новых партий

Полный протокол: `experiments/blindspots/plan.json`. Новый отбор — 12 seed
202611010–202611021; отдельный контроль — 60 seed202611100–202611159.
В 76 найденных JSON результатов (106 уникальных seed) пересечений нет.
Технический seed202611009 использован только для двухходовой проверки runner.

Три разных механизма: прогресс (10000/20000/40000 за каждую готовую11),
геометрия (1000/2000/4000 за легальное направление в leaf при ровно двух11),
вычисления (depth4 при >=двух11 и <=1/3/5 пустых, иначе3). Первый механизм —
повтор ранее проверенной семьи, а не полноценная staged value или rollout.
Mobility — ограниченный proxy геометрии, не доказанная оценка достижимости.
Углубление покупается дополнительным CPU; равенство бюджета не заявляется.

Первый раунд: progress20000/mobility2000/focus3; второй:
progress10000/mobility1000/focus1; третий: progress40000/mobility4000/focus5.
Лидер начинается с baseline и меняется только при строго большем числе побед;
порядок разрешения ничьих задан в plan. Две последовательные серии уточнений
без роста лидера означают локальное плато. Если рост продолжается, новый
отборочный раунд заранее фиксируется отдельно до его запуска.

После плато один лучший кандидат замораживается, даже если не обошёл baseline,
и проходит новый парный контроль без дальнейшего подбора. Для подтверждения
офлайн-улучшения нужны больше побед, односторонний точный парный p<=0.05 и
отсутствие limit. Малые эффекты такой контроль может не обнаружить.
Default не меняется без отдельной проверки8/10с и правил/сценария телефона.

Все варианты генерируются из сохранённого `experiments/strategy/baseline.cpp`.
В каждом одинаково добавлены счётчики узлов и обрезанных отрицательных максимумов;
они не меняют оценок и предназначены только для однопоточных fixed-depth запусков.
Дополнительные exports не используются в бюджетном многопоточном поиске.
Контракты проверены `python3 experiments/blindspots/validate.py`: 83 поля,
10 движков, переходы/цель, формулы/вращения, точное совпадение baseline-оценок,
двухходовое совпадение с существующим симулятором. `validation.json` сохраняет
числовой свидетель: baseline уравнивает L/R примерно до1e-6, signed-reference
различает их. Частота эффекта на реальных траекториях пока неизвестна.

Сборка и 47 обязательных тестов прошли до экспериментов; вывод сохранён в

Исходный числовой пол не исправлен: это отдельный механизм, иначе нельзя

## Воспроизведение

```sh
sh vendor/build.sh
python3 experiments/blindspots/lab.py build baseline
python3 experiments/blindspots/lab.py run baseline
```

Повторить build/run с именами из plan. Для контроля добавить `--stage holdout`;
для существующего результата обязателен `--resume`. Сборка сохраняет исходник
и manifest; бинарники в игнорируемом build. После пересборки SHA бинарника
может отличаться: для resume нужен исходный бинарник, несовместимый checkpoint
не перезаписывается. Для чистого повторения использовать новый worktree и
сохранить оригинальные JSON отдельно. Одновременно максимум два процесса;
каждый пишет только свой каталог. Все партии checkpoint-ятся атомарно.
Время включает конкуренцию процессов и не является чистым microbenchmark.

Модель, равномерность клеток, подвижность/неслияние11 — допущения как в SIMULATION.md.
Плато относится только к этим семействам, seed и глубинам; глобальная
оптимальность и поведение телефона не доказаны. Публикации и память не меняются.

## Числовая диагностика после начала отбора

Счётчики подтвердили отрицательные внутренние максимумы в полных новых
траекториях. Дополнительный signed-reference использует максимум со знаком,
loss=-1e9 и корректный выбор отрицательных корневых оценок. Это меняет и
семантику проигрыша, поэтому не включено молча в кандидаты. На первых пяти
снимках первой/второй11 из первых трёх завершённых базовых отборочных игр
выбор depth3 совпал в5/5. Это не доказывает отсутствия эффекта на других ходах.
Точные поля/оценки/хеши: `numerical-probe.json`, исходник:
`signed-reference.cpp`, воспроизведение: `python3 experiments/blindspots/numerical_probe.py`.
Контроль в этой диагностике не используется.

## Продолжение отбора до плато

Раунд 3 дал focus5=5/12 против предыдущего лидера 4/12. Остановка ещё не
наступила. До следующих партий зафиксирован `extension-plan.json`: соседние
пороги 4/6, затем 2/7. При дальнейшем росте следуют пары вплоть до полного
конечного диапазона 0–16. Стоп после двух серий без роста; при исчерпании
сетки плато относится к перечисленным порогам. Контроль не начат.

`extension.py` — отдельная замороженная копия runner с исходной логикой,
своей таблицей вариантов и fingerprint. Исходные lab.py/plan.json сохранены,
поэтому прежние checkpoint остаются совместимыми. Команды аналогичны lab.py,
но с `extension.py`; batch получает `--runner extension.py`.

## Завершённый отбор

216 полных партий на 12 общих новых seed, 18 политик вместе с базой.
Это 12 независимых seed отбора, а не 216 независимых seed. Лимитов нет.

| Политика | Победы из 12 |
|---|---:|
| Baseline depth3 | 2 |
| Progress 10000 / 20000 / 40000 | 3 / 2 / 4 |
| Mobility 1000 / 2000 / 4000 | 1 / 4 / 4 |
| Focus: пустых <=1 / 2 / 3 / 4 / 5 | 2 / 2 / 4 / 3 / 5 |
| Focus: пустых <=6 / 7 / 8 / 9 / 10 / 11 | 4 / **6** / 5 / 5 / 5 / 5 |

Лидер `focus7`: depth4 только при >=двух11 и <=семи пустых, иначе depth3.
После него раунды 8/9 и 10/11 не улучшили число побед: две серии без роста,
заданный критерий локального плато выполнен. Оставшиеся пороги из резервного
плана не запускались. Ни staged value/rollout, ни всё пространство политик
этот цикл не исчерпывает.

Цена на отборе: 7.639 млрд оценок легальных внутренних продолжений против
4.123 млрд у базы (1.85×). Это счётчик работы дерева, не число уникальных
позиций и не все операции CPU. На depth4 пришлось 4128 из 21922 ходов (18.8%).
Время 179.91 против 169.81 с включает разные периоды конкуренции процессов;
делать из него вывод о чистом ускорении/замедлении нельзя. У mobility счётчик
дерева не включает четыре дополнительные проверки легальности в leaf.

Проверка всех focus-политик подтвердила совпадение с базой полей и номеров
ходов появления первой/второй11. До заданной фазы поведение сохранено.
`verify_results.py` проверяет каждый конечный goal/loss, отсутствие лимитов,
seed, счётчики глубины, модель, формулы summary и происхождение исходников.
`resume-checks.json` подтверждает отсутствие повторов и отказ от перезаписи
на реальном CLI обоих runner. Итоги раундов: `integrity.json`.
