# Новый офлайн-цикл: 1 ноября 2026

Новый независимый контроль поддержал `focus7`: **29/60 побед против 18/60**,
парный односторонний **p=0.01734**, при примерно удвоенном объёме поиска.
Завершены 336 партий и заданное локальное плато. Политика сохранена отдельно;
рабочий default и телефон не менялись. Ниже — протокол, данные и повторение.

Отдельная ветка `local/strategy-blindspots-20261101` от `61158f5`.
Основной checkout, прежние worktree, телефон и runtime не меняются.

До новых партий выполнен отдельный аудит со свежим контекстом. Нативная роль
не обнаружилась; применён предусмотренный скиллом fallback с полными инструкциями
TOML и gpt-6.1-sol/high. Отчёт: `experiments/blindspots/BLINDSPOT-REVIEW.md`.
Координатор воспроизвёл прежние 20/60 против 18/60 и числовой свидетель нулевого
пола. Исходный движок, bot.py и benchmark.py побитно соответствуют baseline.

## Зафиксировано до новых партий

Полный протокол: `experiments/blindspots/plan.json`. Новый отбор — 12 seed
202611010–202611021; отдельный контроль — 60 seed202611100–202611159.
В 76 найденных JSON результатов (106 уникальных seed) пересечений нет.
Технический seed202611009 использован только для двухходовой проверки runner.

Три разных механизма: прогресс (10000/20000/40000 за каждую готовую 11),
геометрия (1000/2000/4000 за легальное направление в leaf при ровно двух 11),
вычисления (depth4 при >=двух 11 и <=1/3/5 пустых, иначе 3). Первый механизм —
повтор ранее проверенной семьи, а не полноценная staged value или rollout.
Mobility — ограниченный proxy геометрии, не доказанная оценка достижимости.
Углубление покупается дополнительным CPU; равенство бюджета не заявляется.

Первый раунд: progress20000/mobility2000/focus3; второй:
progress10000/mobility1000/focus1; третий: progress40000/mobility4000/focus5.
Лидер начинается с baseline и меняется только при строго большем числе побед;
порядок разрешения ничьих задан в plan. Две последовательные серии уточнений
без роста лидера означают локальное плато. Если рост продолжается, новый
отборочный раунд заранее фиксируется отдельно до его запуска.

После плато один лучший кандидат замораживается, даже если не обошёл baseline,
и проходит новый парный контроль без дальнейшего подбора. Для подтверждения
офлайн-улучшения нужны больше побед, односторонний точный парный p<=0.05 и
отсутствие limit. Малые эффекты такой контроль может не обнаружить.
Default не меняется без отдельной проверки 8/10 с и правил/сценария телефона.

Все варианты генерируются из сохранённого `experiments/strategy/baseline.cpp`.
В каждом одинаково добавлены счётчики узлов и обрезанных отрицательных максимумов;
они не меняют оценок и предназначены только для однопоточных fixed-depth запусков.
Дополнительные exports не используются в бюджетном многопоточном поиске.
Контракты проверены `python3 experiments/blindspots/validate.py`: 83 поля,
10 движков, переходы/цель, формулы/вращения, точное совпадение baseline-оценок,
двухходовое совпадение с существующим симулятором. `validation.json` сохраняет
числовой свидетель: baseline уравнивает L/R примерно до 1e-6, signed-reference
различает их. Частота эффекта на реальных траекториях пока неизвестна.

Сборка и 47 обязательных тестов прошли до экспериментов; вывод сохранён в
`experiments/blindspots/baseline-tests.txt`. Оба `.command` прошли `zsh -n`.
Исходный числовой пол не исправлен: это отдельный механизм, иначе нельзя
отнести эффект к проверяемым стратегиям.

## Воспроизведение

```sh
sh vendor/build.sh
python3 experiments/blindspots/lab.py build baseline
python3 experiments/blindspots/lab.py run baseline
```

Повторить build/run с именами из plan. Для контроля добавить `--stage holdout`;
для существующего результата обязателен `--resume`. Сборка сохраняет исходник
и manifest; бинарники в игнорируемом build. После пересборки SHA бинарника
может отличаться: для resume нужен исходный бинарник, несовместимый checkpoint
не перезаписывается. Для чистого повторения использовать новый worktree и
сохранить оригинальные JSON отдельно. Одновременно максимум два процесса;
каждый пишет только свой каталог. Все партии checkpoint-ятся атомарно.
Время включает конкуренцию процессов и не является чистым microbenchmark.

Модель, равномерность клеток, подвижность/неслияние 11 — допущения как в SIMULATION.md.
Плато относится только к этим семействам, seed и глубинам; глобальная
оптимальность и поведение телефона не доказаны. Публикации и память не меняются.

## Числовая диагностика после начала отбора

Счётчики подтвердили отрицательные внутренние максимумы в полных новых
траекториях. Дополнительный signed-reference использует максимум со знаком,
loss=-1e9 и корректный выбор отрицательных корневых оценок. Это меняет и
семантику проигрыша, поэтому не включено молча в кандидаты. На первых пяти
снимках первой/второй 11 из первых трёх завершённых базовых отборочных игр
выбор depth3 совпал в 5/5. Это не доказывает отсутствия эффекта на других ходах.
Точные поля/оценки/хеши: `numerical-probe.json`, исходник:
`signed-reference.cpp`, воспроизведение: `python3 experiments/blindspots/numerical_probe.py`.
Контроль в этой диагностике не используется.

## Продолжение отбора до плато

Раунд 3 дал focus5=5/12 против предыдущего лидера 4/12. Остановка ещё не
наступила. До следующих партий зафиксирован `extension-plan.json`: соседние
пороги 4/6, затем 2/7. При дальнейшем росте следуют пары вплоть до полного
конечного диапазона 0–16. Стоп после двух серий без роста; при исчерпании
сетки плато относится к перечисленным порогам. Контроль не начат.

`extension.py` — отдельная замороженная копия runner с исходной логикой,
своей таблицей вариантов и fingerprint. Исходные lab.py/plan.json сохранены,
поэтому прежние checkpoint остаются совместимыми. Команды аналогичны lab.py,
но с `extension.py`; batch получает `--runner extension.py`.

## Завершённый отбор

216 полных партий на 12 общих новых seed, 18 политик вместе с базой.
Это 12 независимых seed отбора, а не 216 независимых seed. Лимитов нет.

| Политика | Победы из 12 |
|---|---:|
| Baseline depth3 | 2 |
| Progress 10000 / 20000 / 40000 | 3 / 2 / 4 |
| Mobility 1000 / 2000 / 4000 | 1 / 4 / 4 |
| Focus: пустых <=1 / 2 / 3 / 4 / 5 | 2 / 2 / 4 / 3 / 5 |
| Focus: пустых <=6 / 7 / 8 / 9 / 10 / 11 | 4 / **6** / 5 / 5 / 5 / 5 |

Лидер `focus7`: depth4 только при >=двух 11 и <=семи пустых, иначе depth3.
После него раунды 8/9 и 10/11 не улучшили число побед: две серии без роста,
заданный критерий локального плато выполнен. Оставшиеся пороги из резервного
плана не запускались. Ни staged value/rollout, ни всё пространство политик
этот цикл не исчерпывает.

Цена на отборе: 7.639 млрд оценок легальных внутренних продолжений против
4.123 млрд у базы (1.85×). Это счётчик работы дерева, не число уникальных
позиций и не все операции CPU. На depth4 пришлось 4128 из 21922 ходов (18.8%).
Время 179.91 против 169.81 с включает разные периоды конкуренции процессов;
делать из него вывод о чистом ускорении/замедлении нельзя. У mobility счётчик
дерева не включает четыре дополнительные проверки легальности в leaf.

Проверка всех focus-политик подтвердила совпадение с базой полей и номеров
ходов появления первой/второй 11. До заданной фазы поведение сохранено.
`verify_results.py` проверяет каждый конечный goal/loss, отсутствие лимитов,
seed, счётчики глубины, модель, формулы summary и происхождение исходников.
`resume-checks.json` подтверждает отсутствие повторов и отказ от перезаписи
на реальном CLI обоих runner. Итоги раундов: `integrity.json`.

Кандидат `focus7` заморожен в `finalist.json` и коммите `646a807` до начала
контроля. Выбор другого кандидата или изменение параметров после просмотра
контроля запрещены протоколом. Все зафиксированные хеши проверены после него.

## Новый независимый контроль: результат

60 новых seed 202611100–202611159, один заранее выбранный кандидат:

| Политика | Победы | Проигрыши | Лимиты | Оценки внутренних продолжений |
|---|---:|---:|---:|---:|
| Baseline depth3 | 18/60 (30.0%) | 42 | 0 | 20.793 млрд |
| Focus7: depth3/4 | **29/60 (48.3%)** | 31 | 0 | 41.447 млрд |

Разница наблюдаемой частоты побед **+18.3 процентного пункта**. Кандидат
приобрёл 17 побед и потерял 6 побед базы; 37 исходов совпали. Заранее заданный
точный односторонний парный тест: **p=145499/8388608=0.0173448324**.
Условия офлайн-принятия выполнены: больше побед, p<=0.05, ни одного limit.
Это свидетельство улучшения в принятой модели на глубинах 3/4, а не гарантия
такой частоты в следующих партиях или на телефоне. По контролю не выбирались
другие варианты, не продлевалась выборка и не менялись параметры.

Обе политики дошли до двух 11 на одних 42 seed; поля и номера ходов первой/
второй 11 побитно совпали. После достижения двух 11 победили 18/42 и 29/42.
Это описательная локализация различий в проверенном эндшпиле, не новая
независимая выборка. Метрика побед всего контроля остаётся основной.

Цена: **1.993×** оценок внутренних продолжений. На depth4 пришлось
25483 из 111600 ходов (22.8%). Наблюдаемое суммарное время — 907.80 против
498.50 с; запуски конкурировали, а после завершения базы кандидат работал один.
Эти времена не являются строгим замером при одинаковом CPU-бюджете.
Улучшение требует дополнительного поиска; эффективность при равном бюджете
не проверена. Числовой нулевой пол сохранён в обеих сравниваемых политиках.

**Результат принят как отдельная офлайн-политика; default не переключён.**
Режим 8/10 с, две 11 на телефоне и полный живой цикл требуют отдельной проверки.
Рабочая папка бота и телефон сохранены.

Итого **336 новых полных партий**:216 отборочных и 120 контрольных,
12 уникальных seed отбора и 60 новых контрольных. Технические двухходовые
проверки в это число не включены. Все партии, исходники, manifests, снимки
первой/второй 11 и счётчики сохранены в `experiments/blindspots/`.

- `summary.json` — парные приобретения/потери, p и цена.
- `paired-check.json` — независимый пересчёт биномиального хвоста и 42 общих seed второй 11.
- `baseline/holdout.json`, `focus7/holdout.json` — все 120 контрольных партий.
- `finalize.py` — сверка заморозки, целостности данных и итогового сравнения.
- `integrity.json` — все 336 исходов и последовательность локального плато.
- `provenance.json` — компилятор, Python, флаги и происхождение движков.

Сборка,47 обязательных тестов и `zsh -n` прошли; core-файлы `bot.py`,
`benchmark.py`, `vendor/engine_adapted.cpp` с baseline не менялись.
Новые контракты проверены отдельно, все итоговые артефакты и заморозка сверены.
Исходный audit-report остаётся неизменным; его числовой риск исследован
отдельно, без смешивания с эффектом выбранной политики.

## Проверка и повторение

Пересчитать статистику сохранённых JSON без сборки и новых партий:

```sh
python3 experiments/strategy/stats.py experiments/blindspots/baseline/holdout.json experiments/blindspots/focus7/holdout.json
```

В этой рабочей копии сохранены исходные бинарники: `python3
experiments/blindspots/finalize.py` проверит также их замороженные хеши.
Для завершённого checkpoint команды `run ... --resume` только проверяют
совместимость и пропускают партии. После пересборки бинарников их SHA может
измениться; такой resume намеренно отвергается.

Для полного повторения контроля сохраните оригиналы в отдельном worktree:

```sh
git worktree add --detach ../2048-replay local/strategy-blindspots-20261101
cd ../2048-replay
mkdir -p experiments/blindspots/build/reference/baseline experiments/blindspots/build/reference/focus7
mv experiments/blindspots/baseline/holdout.json experiments/blindspots/build/reference/baseline/
mv experiments/blindspots/focus7/holdout.json experiments/blindspots/build/reference/focus7/
sh vendor/build.sh
python3 experiments/blindspots/lab.py build baseline
python3 experiments/blindspots/extension.py build focus7
python3 experiments/blindspots/lab.py run baseline --stage holdout
python3 experiments/blindspots/extension.py run focus7 --stage holdout
python3 experiments/strategy/stats.py experiments/blindspots/baseline/holdout.json experiments/blindspots/focus7/holdout.json
```

Это повтор тех же seed, не новый независимый контроль. Для отбора аналогично
сохраните `training.json` соответствующего варианта и используйте `--stage training`.
`finalize.py` предназначен для оригинального пакета заморозки, а не для новых
бинарников повторения. Другой компилятор/архитектура могут изменить округления;
исторические SHA и версии сохранены, побитное равенство между тулчейнами не обещается.

Следующие непроверенные направления — staged value/rollout, смысл нулевого пола,
чувствительность к модели появлений и одинаковый временной бюджет. Они не
объявляются исчерпанными локальным плато этого цикла. Новое подтверждение после
дальнейшего подбора потребует других, ещё не просмотренных контрольных seed.
