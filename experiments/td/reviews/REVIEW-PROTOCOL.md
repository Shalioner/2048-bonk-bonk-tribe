## Почему протокол согласован

- **Реальный предмет переноса задан проверяемо.** Пин donor — `moporgic/TDL2048@a99f620`; все четыре локальных файла совпали с byte-count/SHA manifest, MIT-лицензия сохранена. В оригинале есть конкретные соответствия: `method::isomorphic::estimate/optimize` (`2048.cpp:1497–1536`), ошибка `exact-estimate` (`1771–1775`) и последовательный forward TD(0) с финальным target (`2038–2057`). API переносит эти update/afterstate механизмы с явно изменённой целью, не обещает использовать готовые веса классической2048. Само наличие архива ещё не доказывает фактический перенос будущим trainer — это остаётся предметом уже запланированного ревью его точного commit.
- **Цель Bonk отделена от merge-score.** API задаёт reward0 на нетерминальных переходах, discount1 и terminal goal1/loss0, три точных несливающихся rank11, локальные moves/spawn и отсутствие spawn после goal. TD обновляет предыдущее afterstate по следующему выбранному afterstate; MC использует полный бинарный исход. Clipped-linear representation, паттерны/D4/stages и alpha одинаковы для новых matched MC/TD. Старый sigmoid LR10 вынесен в отдельный historical screen-arm и не подменяет этот learner control.
- **Сравнение MC/TD-teacher контролирует траектории.** `plan.json:17` требует одинаковые teacher, seed, epsilon, старты и число эпизодов, равные trajectory_digest и совместный checkpoint по сумме validation goal-tuples. Teacher по API не использует активную learned-модель. Отдельный td_selfplay меняет поведение после warmup; протокол прямо запрещает однофакторную причинную интерпретацию его сравнения с matched MC. Если он станет finalist, holdout будет проверять весь этот вариант, а не изолированный эффект TD-target.
- **Splits согласованы.** Независимо пересчитаны диапазоны pool512, training131072, три validation×64, screen24 и holdout60. Они попарно не пересекаются и не пересекаются с426 seed сохранённого inventory. Inventory содержит1205 записей файлов/0 ошибок; само широкое сканирование архивов здесь не повторялось. Validation намеренно использует train-only cap-pool для выбора checkpoint и не называется независимым full-game контролем. Screen/holdout — новые полные старты; pool не берётся из их исходов.
- **Остановка ограничена заранее.** Milestones2048/8192/16384/32768/65536/131072, минимум3 проверки, остановка только после двух последовательных отсутствий улучшения. Matched arms останавливаются/выбираются совместно, selfplay имеет отдельный заранее заданный цикл. Достижение cap без выполнения критерия остановки не даёт основания назвать результат plateau. Малый validation может давать шумный выбор; протокол не выдаёт это за доказанную причину будущего отрицательного результата или глобальную оптимальность.
- **Holdout не используется для настройки.** Выбирается один TD-arm по screen, затем замораживаются модели, runner, статистика и реальные binary. Holdout содержит heuristic, matched MC и этого одного TD на60 парных seed. Совместное подтверждение требует TD>heuristic и TD>matchedMC, двух заранее объявленных односторонних точных парных p<=0.025, screen promotion и отсутствия limit. Повторного выбора finalist по holdout нет. Cost отдельно различает nominal10мс и фактическое choose wall на завершённый ход; равная actual-цена не утверждается без±10%.
- **Limits/provenance не ослаблены в контракте.** Ограниченный эпизод не получает loss/MC-label, стадия останавливается без принятия частичных весов; resume должен сверять config/source/binary/pool/model и точный seed-prefix, current/milestone хранятся раздельно. В будущем runner эти требования должны быть фактически реализованы; в текущем root его ещё нет, поэтому проверять его поведение сейчас нельзя.

## Статический core integration

Обе ранние goal-точки переключают learned MC/TD в шкалу1 (`engine_adapted.cpp:378,395`); ручная эвристика сохраняет прежнюю шкалу. Dispatch листа выбирает TD только при загруженной TD-модели. Successful load одного формата очищает другой; failed load возвращается до очистки действующего другого формата. `configure_value_model(None)` очищает оба через общий clear. Python сначала распознаёт magic и строго загружает соответствующий формат, затем вызывает native load. Новые символы optional, существующий API2/default legacy/model-off не переключаются. В просмотренном diff нет изменения cache, scheduler, spawn или правил слияний.

Интеграционные тесты статически покрывают goal/scale, переключение форматов, очистку, failed-load preservation и отказ старой MC-библиотеки от TD opt-in. Они не запускались: модуль/TD header и trainer намеренно ещё находятся в работе другого исполнителя. Их отсутствие сейчас не оформляется как дефект промежуточного diff.
