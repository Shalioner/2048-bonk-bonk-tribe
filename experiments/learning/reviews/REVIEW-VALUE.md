# Независимое ревью обучаемой afterstate-оценки

## Область

Исходная задача: компактная MC-afterstate value для трёх несливающихся rank11, стадии 0/1/2, D4, эпизодное взвешивание, раздельные train/validation seed, Brier admission/early stopping, строгий файл модели и optional API2/Python/CLI seam. Default должен оставаться legacy без модели; никакого телефона, ADB или публикации.

Исходники не менялись. Implementation-документ и общий лог 74 тестов использовались как контекст; проверки ниже выполнены независимо. Предыдущий `REVIEW-CORE.md` сохранён.

## Findings

Подтверждённых дефектов P0–P3 в проверенном диапазоне не найдено. Корректность механизма не доказывает качество ещё не обученного игрового кандидата.

## Проверено по коду и новым тестам

- **Цель и afterstate.** `value_model.py:85–99,164–172`, `vendor/value_model.h:75–115` задают goal1, terminal loss0, только точный rank11 считается CAP, равные уровни >=11 не дают легального слияния. Приоритет goal перед loss сохраняется. Стадии считаются по количеству CAP. Inference Python/C++ согласован на трёх стадиях, терминалах и D4-преобразованиях.
- **Место применения.** Лист `score_tilechoose_node` представляет состояние после собственного хода до появления плитки; learned value применяется через `score_heur_board`, как и прежняя эвристика. Обе ранние goal-точки переключены на1 (`vendor/engine_adapted.cpp:371,387`), `score_move_node` сохраняет loss0/нулевой максимум. Общая константа `+1e-6` только у верхнеуровневых легальных ходов не меняет их порядок. Clear восстанавливает исходную эвристику.
- **MC и разделение.** `value_model.py:112–152,203–209` проверяет один бинарный исход на seed, противоречия терминальному полю, положительные конечные веса и отсутствие общих seed у train/validation. Веса внутри каждой партии нормируются до суммы1, включая уже переданные `1/n`; длина партии не создаёт дополнительную суммарную массу.
- **Обучение.** `value_model.py:210–285` начинает с нулевых tuple-весов и train-stage prior, использует нормированные веса в minibatch logistic SGD, не обновляет терминалы и сохраняет параметры выбранной эпохи. Validation используется для выбора эпохи и admission, без validation admission=False. Brier и prior сравниваются с одинаковым эпизодным взвешиванием; история и происхождение сохраняются.
- **Файл.** `value_model.py:287–359` проверяет header, точный размер, CRC, JSON/архитектуру, SHA payload и finite-параметры; запись атомарна. `vendor/value_model.h:31–72` проверяет фиксированный header/rules/target, размер, CRC, IEEE754 и finite, затем одним заключительным этапом заменяет параметры. Повреждённый файл не заменяет ранее загруженную модель. Native JSON намеренно opaque; строгая Python-проверка выполняется до native load в `bot.py:335–348`.
- **Потоки и кэш.** Native inference является const и только читает полностью загруженные веса; локальные/статические признаки не изменяются. Контракт требует load/clear между поисками. Каждый solve использует новые eval_state, поэтому при соблюдении этого контракта не остаётся cache от другой модели.
- **Совместимость и opt-in.** Новые символы привязываются условно, API остаётся2, без `--value-model` выполняется clear/no-op для старой библиотеки. Запрос модели на старой библиотеке явно отклоняется. CLI загружает/проверяет модель до lock и ADB (`bot.py:383–395`); отсутствие модели не меняет default policy.

## Границы следующей приёмки

1. В `ValueModel.fit` значение `min_delta` по умолчанию равно1e-6 и используется также для admission (`value_model.py:187,282–283`). Фиксированный протокол требует улучшение Brier на0.001. Caller обучения должен явно передать `min_delta=0.001` либо отдельно проверить эту планку; документированный пример её передаёт. Сам default библиотеки не является доказательством прохождения планового gate.
2. Модуль получает готовые записи и бинарные исходы. Он не может установить, что caller действительно сохранил afterstate до spawn и не превратил лимит ходов в проигрыш. Это следует проверять в сборщике данных/экспериментальном runner вместе с непересечением новых seed и происхождением данных.
3. Загрузка модели не запрещена по флагу `validation_gate_passed`: seam допускает диагностику нейтральных и отклонённых моделей. Допуск learned arm к игровому сравнению остаётся обязанностью runner по зафиксированному протоколу.
4. Load/clear во время активного native поиска контрактом запрещены, программного mutex нет. Для штатного последовательного CLI и чтения весов рабочими потоками это соблюдено; будущему concurrent caller потребуется своя синхронизация.
5. Цена inference и рост побед не проверены этим ревью. Для итогового вывода нужны отдельные validation/holdout, ограничения фиксированного протокола и фактическая стоимость на ход. Координатор сообщил об уточнении cost-проверки до новых партий; это не часть commit fe0359c и здесь не пересматривалось.

Решение об интеграции и экспериментальной приёмке остаётся за координатором.
