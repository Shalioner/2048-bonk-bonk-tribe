# Альтернативные математические политики поиска без ML

Новая ветка local/strategy-search-alternatives-20261102 от01b659f. Прежние
циклы весов и CAP-геометрии сохранены вместе с отрицательными результатами.
Здесь не меняются правила, цель3×11, leaf-эвристика или её глобальные веса.
Телефон, runtime merge-game-bot, чужой main и архивы не трогаются.

Проверяются четыре разных подхода:

1. D4 canonical recurrence. После cutoff перед cache key нормализуется сам
   раскрываемый chance board, а не только ключ. Cached/reference делают одну
   recurrence; ожидается объединение симметричных состояний, но преобразования
   имеют стоимость. Baseline/новый порядок могут различаться float-rounding.
2. Serial shallow roots. Уровень2 считается последовательно без запуска четырёх
   потоков; с уровня3 остаётся прежний parallel search. Это уменьшает накладные
   расходы короткого прохода, но лишает его параллелизма. Deadline/discard и
   отдельные eval_state для направлений сохраняются.
3. Precision first. Первый вероятностный порог1e-5 вместо1e-4 при той же глубине8.
   Более точный chance search может уменьшить достигнутую глубину. Сам native
   core здесь побайтно прежний, меняется список порогов frontend.
4. Перераспределение времени. На каждый choosecall начисляется10мс; из остатка
   оплачивается фактический choose wall. Пока CAP<2, предел10мс/call; при двухCAP
   можно использовать накопленное время до40мс/call. Overshoot сохраняется как
   долг, а не списывается. Это ДРУГОЙ ресурсный режим: одинаковым жёстким лимитом
   на ход его называть нельзя. Native core и эвристика остаются прежними.

Базовая политика и четыре альтернативы испытываются отдельно, без комбинаций.
До партий фиксируются новый план, SHA фактических сборок, source frontend,
неиспользованные seed и правила отбора. Для контроля выбран N=100 пар заранее:
предыдущий same-baseline timed repeat показал большой разброс, расширять N
после просмотра p запрещено. Самые тяжёлые вызовы bank40ms сохраняют прежний
API-гейт budget+50ms. Median/p95/max/above10ms и суммарный CPU будут показаны
отдельно от nominal allowance и total wall.

Это не ML и не обучение оценок. Отбор сам по себе не подтверждает прирост.

## Зафиксированный протокол

План: `experiments/search_alternatives/plan.json`. Отбор:16 новых seed
2400000000..2400000015, пять политик,80 партий последовательно с ротацией порядка.
Выбор по числу целей; при равенстве преимущество базе, затем меньшему фактическому
wall/ход и порядку объявления. Контроль:100 других seed2500000000..2500000099,
200 партий с чередованием порядка базы и заранее замороженного финалиста.
При двух последних раундах без роста лучшего результата фиксируется локальное
плато; иначе — исчерпание заранее ограниченного набора. Комбинации не подбираются.
Улучшение подтверждается только для небазового финалиста с большей долей целей,
точным односторонним парным p<=0,05 и без партий, прерванных лимитом6000 ходов.
Четыре политических раунда не являются четырьмя независимыми подтверждениями.
Выборка контроля после просмотра результатов не расширяется.

Все партии используют progressive, depth8, номинальный бюджет10мс. Это проверка
короткого бюджета, её нельзя переносить на default10с/ход или процент побед на
телефоне. Модель появлений и правила Bonk остаются рабочими допущениями.

До первой партии пройдены9 нативных тестов и31 тест протокола, включая budget,
симметрии, cache/reference, serial/reference, reset порогов, ledger с долгом,
100 контрольных пар в mock и достижение четырёх CAP одним ходом. Базовая сборка
побайтно использует e28aad0; её оценки и физика точно совпали со старой ручной
моделью в124 случаях на31 сохранённом поле. Эти поля не являются новым контролем.
Фактические исходники, compiler/flags, SHA библиотек и логи сохранены в
`verification/search-alternatives/`; библиотеки — вне Git в соседнем
`../native-engines`. Основной `vendor/engine_adapted.cpp` не меняется.

Команды после сборки (этапы screen/freeze/control запускают один раз):

```sh
python3 experiments/search_alternatives/run.py build
python3 experiments/search_alternatives/run.py screen
python3 experiments/search_alternatives/run.py freeze
python3 experiments/search_alternatives/run.py control
python3 experiments/search_alternatives/run.py finalize
```

Для законченного цикла `screen --resume` и `control --resume` только проверяют
сохранённый checkpoint; для прерванного продолжают точный префикс. Смена источника,
плана, модели среды, списка seed, библиотеки или набора freeze останавливает цикл.

Финалист/сырые данные/SHA заморожены до первой контрольной партии; их нельзя
менять по будущим контрольным результатам.

## Восстановление и проверка сохранённого результата

В Git находятся source/compiler/flags/SHA и полные данные. Измеренные native
библиотеки сохранены в соседнем `../native-engines`, также упакованы в
`../search-native-engines.tar.gz`. Обычная пересборка не подменяет их: новый
бинарник может иметь другой SHA даже при той же формуле. Для нового checkout
с исходными файлами и архивом:

```sh
sh vendor/build.sh
python3 verification/search-alternatives/restore_build.py ../native-engines
python3 verification/search-alternatives/recount.py
python3 experiments/search_alternatives/run.py finalize
```

Restore проверяет sources/библиотеки/C++/точные bytes manifest до записи;
существующий build проверяется без перезаписи. Finalize валидирует законченный
контроль и пересоздаёт ту же сводку без новых игр. Recount проверяет сырые исходы
и записанный ledger, но полные траектории ходов не сохранены. Timed игры сами
по себе зависят от ОС и нагрузки, повтор не обязан дать прежний счёт.
Восстановление проверено в отдельном новом detached checkout отeda79b5 без build:
пять архивных библиотек восстановлены, recount280/25SHA и finalize прошли;
Git остался чистым, сводка не изменилась, новых партий не было. Полные логи
`restoration-tests.txt` и `restoration-finalize.txt` сохранены рядом с проверками.

## Отдельный запуск выбранной политики

`play_search_alternative.py` добавляет opt-in для измеренного banked_endgame.
Он до запуска игры читает и проверяет frozen control/paired criterion/summary
SHA, native/source SHA, thresholds и профиль. Незавершённый или неподтверждённый
контроль, подмена источников и другие бюджеты/глубины/политики отвергаются.
Проверка не вызывает finalize и не переписывает старые результаты.
Единый ledger на одну игру использует те же allocate/charge helpers runner;
расход считается по внешнему wall, включая None и исключения, долг сохраняется.
Базовый `bot.py`, его default10с и прежние command-файлы не переключаются.

```sh
python3 play_search_alternative.py --help
# Отдельный запуск бота с политикой10мс allowance / до40мс при двух CAP:
python3 play_search_alternative.py
```

Поддерживаются прежние --serial/--steps/--delay/--dry-run. Для этой команды
--think допускает только0.01, --depth8, --search-policy progressive;
другие значения отклоняются до импорта native/runtime. Баланс не переносится
между запусками и не подразумевает, что уже существующая партия заработала
credit до старта бота. Политика измерена на полных симуляциях с начала партии.

9 новых entry-тестов прошли с подменённым runtime, в том числе помощь/ошибочные
аргументы без native/ADB, отрицательные gates, маршрутизация, ledger/None/
исключения и восстановление состояния. ROOT отдельно прошёл реальный read-only
gate с пятью архивными DLL и проверил API2/11/3/thresholds; хеши игровых данных
до/после совпали. Bot.main/choose/телефон при этой проверке не вызывались.
Всего в цикле прошли49 новых unit-тестов (native9, runner31, entry9) и124 случая
fixed-depth parity. Help и логи сохранены в `verification/search-alternatives/`.
Живой запуск телефона и качество новой политики на нём остаются непроверенными.
