## Разрешённые конфликты

- Скоростная ветка хранила cache только по полю и старому условию глубины.
  Объединённая flat table сохраняет исправленный ключ ветки победы:
  поле, точная оставшаяся глубина, биты вероятности ветви. Reference API
  и отключение cache сохранены. Ускорение не возвращает старую ошибку поиска.
- Сохранены progressive solver и CLI-default ветки победы, включая передачу
  `policy` через новый `CycleMetrics`-цикл. Python API `choose` остаётся
  legacy по умолчанию для совместимости.
- Перенесены быстрые lookup максимального ранга, обход активных spawn ranks,
  битовый обход пустых клеток, общий transpose, finite validation модели.
  Формула эвристики, порядок суммирования, правила CAP и цель не изменены.
- Сохранены подтверждение двумя кадрами, STOP, проверка фокуса перед жестом,
  ограниченный OCR, full-frame fallback и раздельные метрики полного цикла.
- `search_benchmark.py --mode policy` теперь честно обозначает legacy:
  он не измеряет новый CLI-default progressive.
- PGO не включён. Старый manifest привязан к прежним исходникам и не должен
  приниматься для текущего движка. Стандартная сборка — прежняя O3.

Независимое ревью сравнило обе исходные ветки, затем точный merge-diff и
добавленный launcher. Проверены full-key cache, атомарность модели, сохранение
AST распознавания/защит и progressive solver, anchors всех search variants.
Подтверждённая несовместимость mock `choose` исправлена регрессией с обязательным
аргументом `policy='progressive'`. Блокирующих замечаний к финальному коду нет.

## Запуск

Обычный запуск с точным cache, оптимизациями и progressive:

```sh
sh vendor/build.sh
zsh ./Запустить.command
```

Накопление времени вместе с ускоренным движком:

```sh
python3 play_search_alternative.py --merged-engine
```

Этот отдельный профиль использует 10 мс номинально и до 40 мс при двух CAP
при наличии credit; перерасход остаётся долгом. Он не меняет стандартные
10 секунд обычного запуска. В журнале явно указано
`search_profile=merged_banked_endgame`, `confirmed_improvement=false`.
Частота побед объединённого профиля пока не измерена.

Исторические результаты 63/100 против 49/100 относятся к старому banked
движку и его фактической вычислительной цене. Экспериментальные данные,
fingerprints и контроль не изменены. Без `--merged-engine` проверка сохранена
и отвергает новые исходники, которые не соответствуют старому freeze.
Для повторения исторического результата:

```sh
git worktree add --detach ../2048-banked-historical 078b51a
cd ../2048-banked-historical
sh vendor/build.sh
python3 verification/search-alternatives/restore_build.py PATH_TO_ARCHIVED_LIBRARIES
python3 play_search_alternative.py
```

`PATH_TO_ARCHIVED_LIBRARIES` должен содержать пять точных сохранённых библиотек
из того эксперимента. Они не включены в Git; новая компиляция не заменяет
проверку их hashes. Последняя команда обращается к телефону.

хода, поведение игры и частота побед merged-профиля требуют отдельной живой

файлов. Их содержимое проверено: оно совпадает с уже сохранённым `db204cd`,
который входит в историю speed и объединённого main. Перед обновлением этой
копии локальные файлы дополнительно сохранены в Git stash
`e257e0f05bc11608d966716e1ba030ad9bf09bb5` (сообщение: `Preserve local simulation files before reviewed win-speed merge 2026-11-02`).
Побайтовое содержимое всех семи файлов в stash проверено по SHA-256. Stash
не удалён и не применён поверх уже интегрированных изменений. Рабочая копия
обновлена fast-forward; новые пользовательские файлы не откатывались.
