# Математический решатель без ML

Из новой рабочей версии удалены MC/TD-оценки, загрузчики весов, обучатели и
связанная инфраструктура. CLI бота и timed-симулятора по умолчанию используют
progressive expectimax с ручной эвристикой. Правила трёх несливающихся 11,
модель появлений плиток, накопление наблюдаемых частот и исправленный кэш
сохранены. Python API сохраняет legacy default для совместимости; policy можно
передать явно. Параметры запуска depth8/think10с не изменены.

Ветка `local/strategy-math-20261102` создана от `6e421fe` в отдельном worktree.
Полный ML-архив сохранён в прежней ветке `local/strategy-td-port-20261102`,
старом worktree и Git history; он удалён только из текущей рабочей версии.
Чужой main, телефон, ADB и runtime-папка merge-game-bot не изменялись.
Публикаций, установки зависимостей, платных API и обновлений памяти не было.

## Сохранённая основа

Pure C++ побайтно соответствует `e28aad0`: от прежнего `6e421fe` удалены
только ML-ветки. Базовый вес пустых клеток остаётся **270**. Шкала goal=1e9,
правила, cache(board, remaining depth, probability) и progressive сохранены.
Именно ручная эвристика с progressive дала исторические 26/60 при 10мс/ход.
Этот старый контроль раскрыт; новые 31/60 ниже получены на других seed,
поэтому разница 31 против26 не доказывает улучшение от удаления ML.

После сборки 65 pure/default тестов прошли: 47 прежних bot/benchmark,
14 cache/progressive и4 проверки отсутствия ML/default/spawn. Ещё2 новых
benchmark-теста проверили routing политики;17 runner-тестов — протокол,
возобновление, goal/no-spawn, limits, статистику и полноту freeze. Всего84
уникальных теста. Логи: verification/math-cleanup и verification/math-cycle.
Успешные проверки без изменений кода не повторялись.

На31 сохранённом поле ×2 глубины ×2 threshold все четыре оценки и переходы
побитно совпали с прежним no-ML решателем:124 случая. Это регрессия математики,
не новый win-rate контроль. Независимое ревью подтвердило отсутствие активных
ML-API в DLL, сохранность spawn/правил и физическую сохранность377 удалённых
файлов в старом TD-worktree: [REVIEW-CLEANUP.md](verification/math-cleanup/REVIEW-CLEANUP.md).

## Независимый контроль и решение

Новые60 seed `1700000000..1700000059`, два варианта,120 полных игр;
первый вариант чередуется по seed. Других весов по контролю не выбирали.

| Вариант | Победы | Проигрыши | Limit | Search wall/ход |
|---|---:|---:|---:|---:|
| База, EMPTY270 | 31/60 (51.7%) | 29 | 0 | 4.275мс |
| Кандидат, EMPTY310.5 | 32/60 (53.3%) | 28 | 0 | 4.193мс |

Кандидат приобрёл16 побед и потерял15; точный односторонний парный p=0.5.
Заранее требовались больше побед и p<=0.05: **улучшение не подтверждено**.
Choose-wall ratio=0.98065, в пределах±10%; одинаковый nominal10мс отделён от
фактических затрат. По этому опыту новые веса не включаются: production source
остаётся базовым EMPTY270. ML при этом уже удалён из рабочей версии.

Все176 партий завершены без limits. Первый раунд поднял screen best3→6,
второй его не улучшил. Поэтому stop_reason — **bounded_neighborhood_exhausted**:
проверен фиксированный список соседей, критерий двух раундов без роста не
выполнен. Достигнутое плато и глобальная оптимальность не объявляются.

Данные: [screen.json](experiments/math/screen.json),
[finalist.json](experiments/math/finalist.json), [control.json](experiments/math/control.json),
[summary.json](experiments/math/summary.json). Контроль сохранён в `a0a101b`.
Координатор отдельно пересчитал исходы из нормализованных tuple boards,
парные seed и биномиальный хвост; значения совпали со сводкой.
[Независимый финальный обзор](verification/math-cycle/REVIEW-RESULT.md) подтвердил
все176 исходов, порядок/seed, статистику,26 frozen SHA и цепь коммитов до контроля.
Он также подтвердил, что production core остался EMPTY270, без ML.

Результат относится к принятой модели правил/появлений и короткому бюджету.
При 10сек/ход полный новый win-rate не измерялся; на телефон результат не
переносился. Timed поиск зависит от машины и нагрузки: seed фиксирует RNG,
но не гарантирует одинаковые завершённые глубины при другом wall time.
Нулевой прирост здесь не доказывает бесполезность других математических
улучшений, как прежний отрицательный ML-опыт не доказывал бесполезность всего ML.
